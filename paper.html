Predictive Search Intelligence: Temporal Validation Audit for Content Decay Prioritization

Sohila Khaled Abbas Applied ML Intern & Search Intelligence Engineer Lane: Content Opportunity Scoring

Validation status — not validated

This page documents an exploratory 30,000-row snapshot experiment. The target is derived from the most recent 30-day trend, while the available 90-day aggregate features include that same period. Excluding target-derived columns and splitting clients into separate groups does not remove this temporal overlap. Previously published Precision@K and ROC-AUC figures are withdrawn as predictive-performance claims. No replacement metrics are published. A valid evaluation requires point-in-time features built strictly before a prediction cutoff and a forward outcome window built strictly after it, using dated daily warehouse records.

1. Introduction & Operational Decision Problem

Digital publishing organizations manage thousands of published URLs. Over time, search engine rankings decline due to content staleness, evolving user search intent, and competitive activity. Editors face a critical operational decision: Which decaying URLs should be prioritized for content refresh first?

Misallocating editorial resources incurs substantial cost:

  • False Positive Cost: Wasting ~4.0 editorial hours rewriting healthy or low-volume pages (<100 impressions).
  • False Negative Cost: Unrecovered 25%+ organic traffic drops on high-volume pages (>5,000 impressions).

2. Dataset & Temporal Leakage Audit

The research utilizes the anonymized FlyRank Search Intelligence Dataset comprising 30,000 content items × 44 columns across 32 pseudonymized client domains.

Historical snapshot features impressions_90d, clicks_prev_30d, avg_position, content_age_days, ctr NOT ESTABLISHED — overlapping snapshot window
Outcome Proxy Target clicks_prev_30d - clicks_last_30d Target Outcome Label
Forbidden Exclusions trend_direction, trend_pct, is_declining_label EXCLUDED (Target-derived temporal leakage)

3. Methodology & Client-Grouped Holdout Split

To prevent client-domain contamination, we split the 32 clients into an 80% training set (25 clients) and a 20% client-holdout test set (7 clients). Models were evaluated using Precision@K ($\text{Precision}@50, \text{Precision}@100$) and ROC-AUC on client-grouped split (which does not resolve temporal leakage).

The historical experiment compared a hand-written rule baseline with a Random Forest. This comparison is exploratory only because the available snapshot features overlap the target period.

4. Experimental Results — Withdrawn

The original snapshot metrics are not valid evidence of prospective model performance and are intentionally not reproduced here. The feature aggregates overlap the target observation period. Client-grouped splitting prevents client overlap but does not establish temporal isolation.

Current status: exploratory snapshot results only; no validated performance metrics. See the temporal validation remediation plan.

5. Limitations & Honest Framing

  • Decision-Support Scope: All predictions represent directional priority scoring, not causal guarantees of search rank restoration.
  • Snapshot Data: Evaluation is conducted on a 90-day snapshot; panel search depth varies across client onboard dates.
  • Missing Rank Proxy: avg_position = 0 (1,205 rows) represents unranked missing data and is handled via proxy (default position 50.0).

6. Historical Action Playbook — Illustrative Only

The original queue preview is retained as an example of the intended decision-support output, not as a validated model recommendation. Scores and ranks were produced from the temporally overlapping snapshot experiment and must not be interpreted as reliable predictions.
